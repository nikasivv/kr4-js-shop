## Основа проекта

Проект создан на основе **КР №3** (`kr3-responsive-shop`) — адаптивной версии
HTML/CSS-магазина из КР №1. Вёрстка, адаптивность и доступность сохранены,
в КР №4 добавлена логика на чистом JavaScript без библиотек и фреймворков:
каталог из массива товаров, поиск, фильтры, сортировка, корзина и проверка форм.

## JavaScript-файлы

Скрипты подключаются в конце `body` с атрибутом `defer`. Первым всегда идёт `data.js`,
затем `main.js` (общие функции нужны остальным файлам), затем скрипты конкретной страницы.

| Страница | Подключённые скрипты |
|---|---|
| index.html | data, main, cart, modal, validation |
| catalog.html | data, main, cart, catalog |
| product*.html, cart.html | data, main, cart |
| order.html, contacts.html | data, main, cart, validation |

- `data.js` — массив `products` (10 товаров) и объект `categoryNames` (ключ категории → название). Только данные, без DOM.
- `main.js` — общие функции `formatPrice`, `pluralize` (склонение «1 товар / 2 товара / 5 товаров»),
  `findProductById`, `showMessage` (всплывающее сообщение вместо `alert()`) и мобильное меню из КР №3.
- `catalog.js` — объект состояния `catalogState`, функции поиска, фильтрации и сортировки,
  создание карточек через `createElement`, рендер каталога, пустое состояние, обработчики событий.
- `cart.js` — корзина: добавление, изменение количества, удаление, очистка, расчёт суммы через `reduce`,
  промокод, сохранение в `localStorage`, счётчик в шапке, страница `cart.html` и состав заявки на `order.html`.
- `modal.js` — `<dialog>` «Быстрая заявка» на главной: открытие, закрытие (×, «Отмена», Esc, клик по фону),
  возврат фокуса на кнопку, закрытие после успешной отправки.
- `validation.js` — правила проверки полей, вывод ошибок под полями, статус формы, форматирование телефона,
  имитация отправки; список товаров в форме заявки строится из массива `products`.

На каждой странице скрипт работает только с теми элементами, которые на ней есть
(проверки `if (productsContainer)`, `if (cartList)`, `if (orderDialog)` и т. д.),
поэтому в консоли нет ошибок ни на одной странице.

## Массив товаров

В `js/data.js` — 10 товаров с одинаковой структурой:

```js
{
  id: 3,                         // уникальный номер
  title: 'Пионы в шляпной коробке',
  category: 'compositions',      // bouquets | compositions | field | plants
  price: 3990,                   // число, а не строка
  oldPrice: 4990,                // цена до скидки или null
  isAvailable: true,             // наличие
  badge: 'sale',                 // 'hit' | 'new' | 'sale' | null
  image: 'peony',                // images/peony-400.webp, peony-800.jpg …
  description: 'Пышные пионы и эвкалипт в круглой коробке, стоят без воды.',
  page: 'product-peony.html'     // страница товара или null
}
```

Категории в массиве совпадают со значениями `option` в фильтре и ключами `categoryNames`.
Один товар («Пионы „Белое облако“») — не в наличии, чтобы проверить этот статус.
Изображения 4 новых товаров — цветовые варианты иллюстраций из КР №1 в тех же размерах и форматах.

## Каталог (catalog.html)

Карточки товаров **не написаны в HTML** — в разметке только пустой контейнер
`<div class="products-grid" data-products-container>`. Всё остальное делает `catalog.js`:

```text
products → getPreparedProducts(products, catalogState) → renderProducts() → DOM
                         ↑                                            |
              событие input / change  ← пользователь ←────────────────┘
```

### Состояние каталога

```js
const catalogState = {
  query: '', category: 'all', priceFrom: null, priceTo: null, onlyAvailable: false, sort: 'default'
};
```

Любое событие меняет одно поле состояния и вызывает `updateCatalog()`, которая заново
подготавливает список и выводит карточки.

### Функции

| Функция | Назначение |
|---|---|
| `searchProducts(items, query)` | поиск по названию (`trim` + `toLowerCase` + `includes`) |
| `filterProductsByCategory(items, category)` | фильтр по категории, `'all'` — без фильтра |
| `filterProductsByPrice(items, from, to)` | фильтр по диапазону цены |
| `filterAvailableProducts(items, onlyAvailable)` | только товары в наличии |
| `sortProducts(items, sortType)` | сортировка **копии** массива `[...items].sort()` |
| `getPreparedProducts(items, state)` | применяет все функции по очереди |
| `calculateDiscountPercent(product)` | процент скидки для бейджа «−20%» |
| `countActiveFilters(state)` | число активных фильтров для счётчика на кнопке «Фильтры» |
| `createProductCard(product, index)` | карточка через `createElement`, `textContent`, `classList`, `append` |
| `renderProducts(list)` | очищает контейнер, выводит карточки, количество и пустое состояние |
| `updateCatalog()` | подготовка данных + рендер карточек, счётчика фильтров и чипов категорий |
| `resetCatalog()` | сброс состояния и элементов управления |

### Поиск

Поле `#catalog-search` (`type="search"`) над списком товаров. Событие **`input`** —
список обновляется при вводе каждого символа, регистр не важен («ПИОН» найдёт оба букета с пионами).

### Фильтрация

- **Категория** — `select#category-filter`, событие **`change`**.
  Чипы категорий над каталогом меняют тот же `catalogState.category`, select и чипы всегда синхронны.
  Ссылка `catalog.html?category=plants` сразу открывает нужную категорию.
- **Цена от / до** — событие `input`.
- **Только в наличии** — чекбокс, событие `change`.
- На кнопке «Фильтры» (мобильная версия) — счётчик активных фильтров.

### Сортировка

`select#sort-select`, событие **`change`**: по умолчанию, сначала дешевле, сначала дороже,
по названию А–Я (`localeCompare(..., 'ru')`). Сортируется копия массива,
поэтому порядок «по умолчанию» всегда возвращается к исходному.

### Количество и пустое состояние

- Над списком — «Найдено: 3 товара» (с правильным склонением) в `role="status"`, озвучивается диктором.
- Если ничего не найдено — блок с иконкой, заголовком «Ничего не нашлось», текстом с условиями поиска
  («Товаров по запросу «роза» в категории «Комнатные растения» не найдено…»)
  и кнопкой **«Сбросить поиск и фильтры»**.

## Форма и валидация (validation.js)

Проверяются три формы: заявка на `order.html`, «Быстрая заявка» в модальном окне на главной
и обратная связь на `contacts.html`. У форм стоит `novalidate`: стандартные подсказки браузера
отключены, все сообщения выводит JavaScript.

Правило выбирается по атрибуту `name` поля:

| Поле | Функция | Проверка |
|---|---|---|
| Имя | `validateName` | не пустое, минимум 2 символа, только буквы, пробел и дефис |
| E-mail | `validateEmail` | не пустой, формат `name@example.ru` (регулярное выражение) |
| Телефон | `validatePhone` | 11 цифр, начинается с 7 или 8 (или 10 цифр, начиная с 9) |
| Количество | `validateQuantity` | целое число от 1 до 10 |
| Дата доставки | `validateDate` | необязательная, но не в прошлом |
| Сообщение | `validateMessage` | минимум 10 символов |
| Согласие | `validateAgreement` | чекбокс отмечен |
| Списки (товар, повод) | `getFieldError` | обязательный `select` выбран |

Как это работает:

1. **`submit`** — `preventDefault()`, проверяются все поля.
2. Ошибка выводится **под полем** через `textContent`; поле получает `aria-invalid="true"`,
   текст ошибки связан с полем через `aria-describedby`.
3. Над кнопками — общий статус: «Проверьте форму: 3 поля заполнены с ошибкой.», фокус — на первое поле с ошибкой.
4. **`input`** — как только поле исправлено, ошибка исчезает.
5. **`focusout`** — заполненное поле проверяется сразу при уходе из него.
6. Телефон **форматируется** отдельно от проверки: `89001234567` → `+7 (900) 123-45-67` при уходе из поля.
7. **«Очистить»** (`reset`) убирает все ошибки и статус.

`alert()` в проекте не используется.

## Безопасный вывод данных

- Все данные товаров, текст поиска, промокод, имя и e-mail из формы выводятся только через **`textContent`**.
- Карточки, строки корзины, пункты `select` собираются через **`createElement`** + **`append`**, а не строкой HTML.
- `innerHTML` в проекте **не используется** вообще (в КР №3 он был в счётчике фильтров — заменён).
- Проверка: ввести в поиск `<img src=x onerror=alert(1)>` — в пустом состоянии этот текст
  показывается как обычные символы, скрипт не выполняется. То же с промокодом.
- `localStorage` хранит только `id` и количество товаров, остальные данные берутся из массива `products`.
  Чтение обёрнуто в `try/catch`: повреждённые данные не ломают страницу.

## События

Все обработчики подключены через `addEventListener()`, inline-обработчиков (`onclick`) в HTML нет.

| Событие | Где |
|---|---|
| `input` | поиск, цена, исправление полей формы |
| `change` | категория, сортировка, «Только в наличии» |
| `click` | «В корзину», +/−, «Удалить», «Очистить корзину», чипы, модальное окно, меню |
| `submit` | формы заявки и обратной связи, промокод, панель фильтров |
| `reset` | сброс фильтров и форм |
| `focusout`, `keydown` | проверка поля и форматирование телефона, Esc в меню |
| `form:sent` (своё событие) | форма сообщает об успешной отправке — корзина очищается, модальное окно закрывается |

Кнопки «В корзину» обрабатываются **делегированием**: один обработчик на `document`
ловит клики по `[data-action="add-to-cart"]`, в том числе по карточкам, которые каталог
пересоздаёт при каждом рендере. id товара хранится в `data-product-id` (`dataset`).

## Самостоятельные доработки

1. **Корзина** (`cart.js`, `cart.html`):
   - добавление из каталога и со страниц товаров (кнопка «В корзину»), повторный клик увеличивает количество;
   - на странице корзины: кнопки «−» / «+» (от 1 до 10 шт.), «Удалить», «Очистить корзину»;
   - стоимость строки и итог пересчитываются сразу;
   - товар не в наличии добавить нельзя (кнопка «Недоступно» отключена);
   - после перерисовки фокус возвращается на ту же кнопку — корзиной удобно пользоваться с клавиатуры.
2. **Расчёты через `reduce`**: `calculateCartCount` (число товаров), `calculateCartSubtotal` (сумма),
   скидка по промокоду, итог к оплате.
3. **Промокод**: `FLORA10` (−10%) и `VESNA15` (−15%), регистр не важен; неверный код — сообщение об ошибке
   под полем; строка «Скидка по промокоду» появляется только при скидке.
4. **localStorage**: корзина и промокод сохраняются и восстанавливаются после перезагрузки и на всех страницах.
5. **Счётчик в шапке**: ссылка «Корзина» с числом товаров на каждой странице, скрыт при пустой корзине;
   всплывающее сообщение «… добавлен в корзину».
6. **Единый сценарий заказа**: каталог → корзина → «Оформить заявку» → на `order.html` показан состав корзины
   и сумма, поля «Товар» и «Количество» скрываются (и не проверяются); после отправки корзина очищается.
   Без корзины — обычная заявка на один товар; список товаров строится из массива,
   `order.html?product=3` выбирает товар заранее (ссылки со страниц товаров).
7. **Форма**: имитация отправки (кнопка блокируется, текст «Отправляем…», через секунду — сообщение
   «Спасибо, Анна! Заявка подготовлена — флорист перезвонит на номер +7 (900) 123-45-67»), очистка формы,
   общий статус с числом ошибок, форматирование телефона, проверка даты.
8. **Улучшенная карточка и UX каталога**: статус «В наличии / Нет в наличии», бейджи «Хит», «Новинка»
   и «−20%» (процент считается из цен), серое фото у отсутствующего товара, фильтр по цене и наличию,
   счётчик активных фильтров, расширенное пустое состояние с кнопкой сброса, `?category=` в адресе.
9. **Пустая корзина** — отдельное состояние с иконкой и кнопкой «Перейти в каталог».

## Как проверить

1. Открыть `catalog.html` — выводятся 10 карточек, «Найдено: 10 товаров».
2. Ввести в поиск «пион» — 2 товара. Ввести «xyz» — пустое состояние, нажать «Сбросить поиск и фильтры».
3. Выбрать категорию «Комнатные растения» — 3 товара; сортировка «Сначала дороже» — цены по убыванию.
4. Отметить «Только в наличии» — пропадают «Пионы „Белое облако“».
5. Нажать «В корзину» у нескольких товаров — растёт счётчик в шапке, появляется сообщение.
6. Открыть `cart.html`: изменить количество, удалить товар, ввести промокод `FLORA10`; перезагрузить страницу — всё сохранилось.
7. «Оформить заявку» → на `order.html` виден состав корзины. Нажать «Отправить заявку» с пустой формой — ошибки под полями.
8. Заполнить форму (телефон можно ввести как `89001234567`) → «Отправляем…» → сообщение об успехе, счётчик корзины обнулился.
9. На главной нажать «Заказать» у популярного товара — модальное окно с названием товара; Esc закрывает.
10. DevTools → Console на всех страницах — ошибок нет.
